# chemspace

Chemical space 반복 탐색 엔진. **영역을 선택해 분석 대상을 좁히고, 선택한 화합물들만 새로운 도메인 기준으로 다시 클러스터링·배치하는 과정을 반복**합니다.

ChEMBL 승인·임상 약물 집합(ChEMBL_37, 12,804개)을 데이터로 사용합니다.

---

## 핵심 모델

단계마다 두 가지가 독립적으로 결정됩니다.

| 사용자 행동 | 화합물 집합 | 배치 기준 | 메서드 |
|---|---|---|---|
| **영역 선택** | 줄어듦 | 그대로 | `session.select(...)` |
| **필터 적용** | 줄어듦 | 그대로 | `session.restrict(...)` |
| **도메인 전환** | 그대로 | 바뀜 | `session.switch_domain(...)` |

`select`는 "지도의 이 영역", `restrict`는 "이 조건을 가진 것만"입니다. 둘 다 좁히고 둘 다 재배치하므로 같은 종류의 이동이지만, 필터는 **이름만으로 재현되고** 올가미는 그렇지 않아서 경로에 따로 기록됩니다 — `약물층만 남긴 12,804개`와 `선택한 12,804개`는 다른 기록입니다.

세 경우 모두 **선택된 화합물만으로 임베딩을 다시 적합**합니다. 부모 노드의 좌표를 재사용하지 않습니다 — 전체 지도를 확대하는 방식으로는 "물성에서 붙어 있던 화합물이 질환 관점에서 갈라지는" 구조가 나오지 않기 때문입니다.

### 전제가 실제로 성립하는지 측정했습니다

같은 1,200개 화합물에 대해 물성 군집 라벨과 질환 군집 라벨을 비교하면:

```
조정 랜드 지수 ARI = -0.112 ~ 0.018   (0이면 두 관점이 완전히 독립)
물성에서 한 덩어리였던 군집이 질환 관점에서 평균 2.7 ~ 13.5개로 갈라짐
```

5회 실행에서 ARI는 -0.112, -0.002, 0.007, 0.016, 0.018이었습니다. 전부 0 근처이거나 그 아래 — **우연 수준을 넘는 일치가 없다**는 뜻입니다. 두 관점은 사실상 서로 독립이고, 그래서 관점을 바꾸는 것이 정보를 만들어 냅니다.

수치 자체는 흔들립니다. 한쪽 군집이 3~4개뿐일 때 ARI는 표본이 작아 잡음이 크고, 분리 개수도 그 실행의 군집 개수에 따라 달라집니다(위 재현성 항목 참조). 흔들리는 것은 크기이지 부호나 결론이 아닙니다.

이 측정은 `scripts/smoke_test.py`가 매번 수행하므로, 도메인을 추가하거나 특성을 바꾼 뒤에도 전제가 유지되는지 확인할 수 있습니다. **ARI가 0.3, 0.5처럼 뚜렷하게 올라간다면 새 도메인이 기존 도메인과 사실상 같은 것을 보고 있다는 신호입니다.**

### ARI만으로는 모자랍니다 — 군집 응집력

ARI ≈ 0은 **필요조건이고 충분조건이 아닙니다.** 다음 두 경우와 똑같이 들어맞기 때문입니다.

- 물성 군집도 의미 있고 질환 군집도 의미 있는데 서로 다른 것을 본다 ← 우리가 원하는 것
- **둘 중 하나가 그냥 잡음이다** ← 무작위 분할 두 개도 ARI 0입니다

그래서 `scripts/cluster_quality.py`가 나머지 절반을 잽니다 — 각 도메인의 군집이 **그 자체로 뭉쳐 있는가**. 모든 수치는 **귀무값** 옆에 둡니다: 같은 행렬에서 각 특성 열을 따로 섞어(각 용어의 출현 빈도는 유지, 용어 간 동반출현만 파괴) 같은 파이프라인을 돌린 결과입니다.

#### 먼저, 보기 좋은 지도는 증거가 아닙니다

| 도메인 | 지도 위 실루엣 (진짜) | 지도 위 실루엣 (**난수**) |
|---|---|---|
| 물성 | 0.438 | **0.658** |
| 질환 | 0.676 | **0.761** |
| 표적 | 0.717 | 0.682 |
| 모달리티 | 0.619 | 0.483 |

**완전한 난수가 진짜 데이터보다 더 깔끔한 지도를 만듭니다.** UMAP+HDBSCAN은 구조가 전혀 없는 입력에서도 잘 떨어진 덩어리들을 그려 냅니다. 화면이 그럴듯해 보이는 것은 아무것도 보증하지 않습니다.

같은 이유로 **특성 공간 실루엣도 쓸 수 없습니다.** 귀무값은 라벨만 바꾸는 게 아니라 데이터 자체를 바꾸므로, 섞인 행렬 위의 실루엣과 진짜 행렬 위의 실루엣은 비교 대상이 아닙니다 (군집 수를 맞춰도 질환 0.170 vs 0.191, 모달리티 0.033 vs 0.059로 난수가 이깁니다). 실루엣 열은 참고로 출력하되 판단 근거로 쓰지 않습니다.

#### 쓸 수 있는 지표: 외부 라벨과의 일치

WHO의 **ATC 치료분류**는 이 파이프라인을 본 적 없는 사람들이 매긴 라벨입니다. 조정 상호정보량(AMI)은 군집 수에 대해 보정되므로 위 함정에 걸리지 않습니다.

| 도메인 | AMI (진짜) | AMI (난수) | 최빈 라벨 농도 |
|---|---|---|---|
| **표적** | **0.244** | −0.005 | 48.9% |
| 모이어티 | 0.130 | 0.000 | 29.2% |
| 모달리티 | 0.116 | 0.000 | 31.9% |
| 물성 | 0.055 | 0.001 | 25.0% |
| 질환 (ATC 제외) | **0.508** | 0.002 | 73.1% |
| ~~질환 (ATC 포함)~~ | ~~0.713~~ | ~~−0.005~~ | ~~89.9%~~ ← 순환 |

> 이 표는 `min_cluster_size`에 상한을 두기 전의 값입니다 (12,804개에서 57). 현재 기본값 40으로 다시 재면 모이어티 0.179, 표적 0.245, 물성 0.057로 바뀝니다 — 결론은 같고 모이어티만 눈에 띄게 올라갑니다. [군집 세분도](#군집-세분도) 참고.

**다섯 도메인 모두 귀무값을 분명하게 이깁니다.** 난수는 전부 0 근처이고, 진짜는 0.055~0.508입니다. 군집은 잡음이 아닙니다.

효과 크기의 **순서가 생물학적으로 말이 됩니다**. 같은 단백질 계열을 치는 약은 비슷한 질환에 쓰이므로 표적이 가장 높고(0.244), 분자량과 logP는 그 약이 무슨 병에 쓰이는지를 거의 결정하지 않으므로 물성이 가장 낮습니다(0.055). **물성이 낮게 나오는 것이 오히려 측정이 제대로 작동한다는 신호입니다** — 무엇에나 높은 점수를 주는 지표였다면 쓸모가 없습니다.

질환 도메인은 특성에 ATC가 들어가므로 ATC와의 일치가 부분적으로 순환입니다. ATC 항목을 빼고 **MeSH 적응증만으로** 다시 재면 0.713에서 **0.508**로 내려갑니다. 순환이 부풀린 몫이 그만큼이고, 남은 0.508은 진짜입니다 — 세분화된 MeSH 적응증만으로 군집을 만들어도 WHO의 14분할 치료영역이 73% 농도로 복원됩니다.

측정 도구 자체도 양방향으로 검증했습니다 (`tests/test_core.py`): 구조를 심어 두면 찾아내고(AMI > 0.9), **구조가 없으면 찾아내지 않습니다**. 두 번째가 없으면 첫 번째는 의미가 없습니다.

### 부분집합 상대성

도메인이 부분집합에 대해 상대적으로 동작하도록 두 규칙을 적용합니다 ([`domains/base.py`](src/chemspace/domains/base.py)).

1. **연속형 특성은 부분집합 내에서 z-score.** drug-like 1,200개로 좁힌 뒤 의미 있는 분산은 전체 12,804개의 분산이 아니라 그 1,200개 사이의 분산입니다.
2. **부분집합 내 지지도가 없는 이진 특성은 제거.** 선택된 화합물 중 아무도 갖지 않은 MeSH 용어는 Jaccard 거리에 잡음만 더합니다. 임계값은 부분집합 크기에 비례(약 0.2%)해 자동 조정됩니다 — 12,804개에서 1로 고정하면 ~5,000열 잡음 행렬이 되고, 25로 고정하면 300개에서는 모든 특성이 사라집니다.

### 탐색 경로는 트리

로그가 아니라 트리입니다. 이전 노드로 돌아가 다른 영역을 선택하면 기존 가지를 덮어쓰지 않고 **형제 가지**가 추가되므로, "질환 영역 A"와 "질환 영역 B"를 나란히 비교할 수 있습니다.

```
└─ [n1] 전체 12,804개 (물성) · 10군집
   └─ [n2] 물성에서 드래그 선택한 1,200개 · 3군집
      └─ [n3] 질환으로 재배치 (1,200개) · 16군집
         ├─ [n4] 질환에서 드래그 선택한 300개 · 12군집
         │  └─ [n5] 표적으로 재배치 (300개) · 8군집
         │     └─ [n6] 모이어티로 재배치 (300개) · 5군집
         └─ [n7] 질환에서 드래그 선택한 300개 · 0군집      ← 다른 영역을 고른 형제 가지
            └─ [n8] 모달리티로 재배치 (300개) · 3군집
```

`scripts/smoke_test.py`의 실제 출력입니다. 경로 한 줄로 보면:

```
전체 12,804개 (물성)  →  물성에서 드래그 선택한 1,200개  →  질환으로 재배치 (1,200개)  →  질환에서 드래그 선택한 300개  →  표적으로 재배치 (300개)
```

## 도메인

| 도메인 | 배치 기준 | 거리 | 출처 |
|---|---|---|---|
| **물성** `physchem` | MW·cLogP·TPSA·HBD/HBA·RotB·Fsp3·QED 등 13개 기술자 | euclidean | RDKit 계산 |
| **질환** `disease` | MeSH 적응증 다중라벨 + ATC 해부학적 주군 | jaccard | `drug_indication`, ATC 코드 |
| **표적** `target` | 단백질 계열 L1~L3 + 개별 표적 다중라벨 | jaccard | `mechanism`(큐레이션) + `activity`(측정 pChEMBL≥7) → `target_component` → `protein_classification` |
| **모이어티** `moiety` | Murcko 스캐폴드의 ECFP4 비트 | jaccard | RDKit Murcko |
| **모달리티** `modality` | 크기·유연성·고리계 수·아마이드 골격·최대 고리·warhead | euclidean | 규칙 + ChEMBL `molecule_type` |

**모달리티 도메인 설계 주의.** 모달리티는 *라벨*이고, 라벨을 원-핫으로 임베딩하면 k개 점이 겹친 지도가 나옵니다. 그래서 이 도메인은 **모달리티를 규정하는 구조적 특성**으로 배치하고 규칙 기반 라벨은 색으로만 씁니다. 그러면 펩타이드·거대고리·공유결합이 실제로 선택 가능한 영역을 차지합니다.

새 도메인은 `Domain` 두 메서드(`featurize`, `profile`)만 구현하면 추가됩니다. 과제 계획의 학습된 예측 모델이 세션·뷰어 변경 없이 이 자리에 들어갑니다.

### 모달리티 규칙과 warhead 등급

1차 개발의 모달리티는 학습된 분류기가 아니라 규칙입니다. ChEMBL `molecule_type`을 우선 신뢰하고, 저분자는 구조로 세분합니다 (거대고리 → 펩타이드 → PROTAC 후보 → 공유결합 → bRo5 → 저분자).

**warhead는 신뢰도 2등급으로 나눕니다.** 친전자성 작용기를 전부 "공유결합"으로 취급하면 안 됩니다. 범용 Michael acceptor SMARTS는 ChEMBL_37에서 693개를 잡는데 대부분 프로스타글란딘·스테로이드 엔온·칼콘이고, 이게 라벨을 결정하게 두면 공유결합이 1,386개로 부풀면서 654개가 이런 화합물이 됩니다. 그래서 `strong`(설계상 공유결합: β-lactam, acrylamide, haloacetamide, vinyl sulfone, sulfonyl fluoride, epoxide, aziridine, boronic acid, α-aminonitrile, isocyanate)만 라벨을 정하고, `weak`(범용 Michael acceptor, aldehyde, disulfide)는 `covalent_warhead` 컬럼에 기록만 하고 라벨과 지도 좌표에는 영향을 주지 않습니다.

등급 적용 결과 (12,804개):

| 모달리티 | 개수 |
|---|---|
| 저분자 | 10,187 |
| bRo5 | 940 |
| 공유결합 | 677 |
| Protein | 327 |
| 거대고리 | 223 |
| PROTAC/분자접착제 후보 | 220 |
| 펩타이드 | 183 |
| Oligosaccharide / Oligonucleotide | 47 |

공유결합 677개의 구성은 acrylamide 287(ibrutinib 계열), β-lactam 231(페니실린·세팔로스포린), epoxide 58, α-aminonitrile 36, boronic acid 29 등입니다. weak만 매칭된 837개는 원래 라벨(저분자 630개 등)을 유지합니다.

PROTAC 후보는 E3 리간드 모티프(글루타르이미드/CRBN 44개, hydroxyproline amide/VHL 20개)를 1차 근거로 쓰고, 모티프가 없으면 MW·유연성·고리계 수 휴리스틱으로 보완합니다.

### 표적 주석은 두 출처에서 옵니다

`mechanism`은 **큐레이션된 의도** — 그 약이 무엇을 치도록 만들어졌는가. 신뢰도가 높지만 **ChEMBL 전체에서 5,954개 화합물이 천장**이고, 화합물을 아무리 더 모아도 늘지 않습니다.

`activity`는 **측정된 결합력** — 2,450만 건의 실측값입니다. 규모 있는 표적 주석의 유일한 경로입니다. 기본 임계값은 **pChEMBL ≥ 7 (100 nM)** 으로, 화합물이 그 표적에서 실제로 무언가 하고 있다고 말할 만한 세기입니다.

둘은 **같은 용어 공간**을 씁니다. `TGT:EGFR`은 어느 테이블에서 왔든 같은 단백질이고, 접두사를 나누면 같은 표적을 치는 두 화합물이 특성을 공유하지 못하게 됩니다. 출처는 `source` 컬럼에 남아 커버리지 보고와 군집 프로파일에서 구분됩니다.

**화합물당 상위 25개로 제한합니다** (`MAX_ACTIVITY_TARGETS`). ChEMBL의 활성 건수는 그 화합물이 **얼마나 연구됐는지**를 따라갑니다 — 키나아제 패널에 돌려진 약은 측정 표적이 수백 개이고, 똑같이 난잡하지만 덜 조사된 약은 세 개입니다. 제한하지 않으면 표적 지도가 유명한 화합물과 무명 화합물을 갈라놓고 그걸 생물학이라고 부르게 됩니다.

**세포주는 표적이 아닙니다.** ChEMBL의 `activity`는 **어떤 실험이든 그 대상**을 target이라고 부릅니다. 우리가 수집한 활성 쌍의 **35.7%가 CELL-LINE**이었습니다 — 도세탁셀은 세포주 544개와 단백질 2개로 돌아왔습니다. 세포주 측정은 "세포를 죽인다"는 *효과*이지 무엇에 붙는지가 아닙니다. 그대로 두면 표적 지도가 세포독성 항암제들을 **어떤 스크리닝 패널을 거쳤는지**로 묶고 그걸 공유 약리작용이라고 내놓습니다.

그래서 활성 유래 표적은 `PROTEIN_TARGET_TYPES`(SINGLE PROTEIN, PROTEIN COMPLEX, PROTEIN FAMILY 등)로 거릅니다. ORGANISM·TISSUE·ADMET·UNCHECKED도 같이 빠집니다. 이 필터로 커버리지가 48.9%에서 46.7%로 내려가는데, **내려가는 게 맞습니다** — 세포주만 갖고 있던 286개 화합물은 표적 주석이 없는 것이 사실입니다.

필터는 **상한을 적용하기 전에** 겁니다. 그래야 화합물의 25칸이 스크리닝 패널이 아니라 진짜 표적으로 채워집니다. 거르고 나면 상한에 걸리는 화합물은 3,843개 중 59개(1.5%)로 줄어듭니다 — 상한이 잡아내던 것의 대부분이 세포주 패널이었다는 뜻입니다.

> 필터는 활성 쪽에만 겁니다. 큐레이션된 `mechanism`은 작고 의도적이어서, 항균제의 표적으로 생물종을 적어 둔 것은 실험 부산물이 아니라 작동 방식에 대한 진술입니다.

> 종(species)은 자동으로 합쳐집니다. 용어가 `target_chembl_id`가 아니라 `target_pref_name`으로 만들어지므로, 사람과 래트의 도파민 D2 수용체는 같은 `TGT:` 항목이 됩니다.

**임계값을 낮춰도 해결되지 않습니다.** 미커버 화합물 300개를 표본으로 재보니 pChEMBL ≥ 6으로 내려도 7%, ≥ 5까지 내려도 14%만 추가됩니다. 나머지는 약하게 붙는 게 아니라 **측정 자체가 없습니다.** 이 구간이 과제 계획의 학습된 표적 예측 모델이 메우려는 지점입니다.

ATC는 2,818개 화합물에 있지만 MeSH가 없는 화합물 **259개만 추가**합니다. 커버리지를 넓히려는 것이 아니라, 약 5,000개의 세분화된 MeSH 용어와 대비되는 14분할 치료영역 축을 제공하고 질환 지도의 색 구분에 쓰입니다.

데이터가 없는 화합물은 그 도메인에서 **원점이 아니라 '미지'** 입니다. 임베딩 적합에서 제외하고 지도 아래 띠에 배치합니다. 그대로 넣으면 Jaccard에서 모든 영벡터가 서로 거리 0, 나머지와 거리 1이 되어 하나의 가짜 밀집 군집을 만들고 실제 구조를 끌어당깁니다.

띠의 크기는 임베딩의 min/max가 아니라 **5~95 백분위(코어)** 기준으로 잡습니다. UMAP은 보통 몇 개 점을 멀리 떨어뜨려 놓는데, 그 이상치까지 포함해 띠 너비를 정하면 미커버 619개가 패널을 덮어 실제 군집이 구석으로 밀립니다.

UMAP은 작고 희소한 Jaccard 입력에서 가끔 NaN/inf 좌표를 내놓습니다. 그대로 두면 해당 점이 그림에서 사라질 뿐 아니라, 좌표 범위를 쓰는 모든 후속 계산(띠 기하, 축 맞춤)이 **전체 점에 대해** NaN이 됩니다. 그래서 임베딩 직후에 비유한 좌표를 해당 열의 중앙값으로 치환하고 `non_finite_coords` 노트에 개수를 남깁니다.

### 루트에서 표적·모이어티가 동그란 이유

전체 데이터를 물성으로 보면 지도에 구조가 생기지만, **표적과 모이어티로 전환하면 거의 원형 덩어리**가 나옵니다. 버그가 아니라 데이터 기하의 정직한 신호이고, 세 가지를 재서 확인했습니다 (`scripts/` 측정 스크립트).

**1. 비트가 무엇을 담는가.** 두 도메인 모두 희소 이진 벡터이고 Jaccard 거리를 씁니다.

- **표적**은 그 화합물이 작용하는 단백질을 토큰으로 켭니다 — 개별 표적 `TGT:`와 단백질 계열 3단계 `L1:/L2:/L3:`. 예: `OFLOXACIN → {L1:Enzyme, L2:Isomerase, TGT:Bacterial DNA gyrase}` (3개). "비트 3개가 켜졌다"는 점수가 아니라 **집합 소속**입니다 — 어휘 수천 칸 중 이 3칸만 1입니다. 서너 개뿐인 이유는 신약 데이터가 "이 화합물을 의도한 표적 하나(+계열 레이블)에 시험"한 기록이기 때문입니다. 어휘는 단백질 수천 종인데 각 화합물은 서너 칸만 채웁니다.
- **모이어티**는 Murcko 스캐폴드의 ECFP4(Morgan r=2) 지문입니다. 비트 하나 = 특정 원형 부분구조(한 원자 + 반지름 2까지의 이웃)의 존재. 예: `PRAZOSIN` 스캐폴드는 **42비트**가 켜집니다 — 원자 약 20개의 연결된 고리 그래프에서 반지름 0/1/2 조각이 겹겹이 ~40개 생기기 때문입니다 (벤젠, 피페라진, 퀴나졸린 등).

**2. 거리가 어떻게 무너지는가 — 두 원인은 다릅니다.**

| 도메인 | 차원 | 켜진 비트(중앙값) | 쌍 거리 (25/50/75%) | 증상 |
|---|---|---|---|---|
| 물성 | 13 (연속) | — | 1.45 / 2.77 / 5.79 (euclidean) | 정상적으로 퍼짐 |
| 표적 | ~320 | 3~4 | 0.667 / **1.000** / 1.000 | **거리 포화** — 쌍의 64%가 완전 분리(거리 1.0) |
| 모이어티 | ~2,030 | 42 | 0.81 / **0.88** / 0.94 | **거리 집중** — 거의 모든 쌍이 0.88 근처 |

표적은 EGFR을 치는 화합물과 GPCR을 치는 화합물이 **공유 비트가 0**이라 거리가 정확히 1.0으로 포화됩니다(쌍의 64%). 모이어티는 반대로 벤젠·피페라진 같은 흔한 조각을 **아무 두 화합물이나 조금씩 공유**해서 거리가 전부 0.88 근처로 몰립니다. 둘 다 결과는 같습니다 — 거리에 대비가 없으면 UMAP이 끌어당기거나 밀어낼 축이 없어 원반이 됩니다.

> 표적이 100%가 아니라 64% 포화인 것은 계열 레이블 `L1/L2/L3` 덕입니다. 서로 다른 두 키나아제는 `TGT:`는 달라도 `L2:Kinase`를 공유합니다. 계열 분류가 이미 "비슷함"을 조금 넣고 있습니다.

**3. UMAP 탓이 아닙니다 — 선형 방법(PCA)도 똑같이 못 폅니다.** 각 도메인을 PCA로 재서 2차원에 얼마나 담기는지 봤습니다.

| 도메인 | 상위 2개 주성분이 담는 분산 | 90% 담으려면 |
|---|---|---|
| 물성 | **73.1%** | 5차원 |
| 표적 | 29.9% | 101차원+ |
| 모이어티 | **6.9%** | 101차원+ |

물성은 정보가 사실상 2~5차원에 있어 2D 지도가 충실한 그림자입니다. 모이어티는 정보의 **93%가 2D 바깥**에 있습니다 — 어떤 방법으로 밀어넣든 버려집니다. PCA(선형)도 2D를 못 만든다는 건 "2D로 펼 구조가 데이터에 없다"는 뜻이고, UMAP이 없는 축을 지어내지 않고 정직하게 원반을 그린 겁니다. t-SNE로 바꿔도 모양만 다른 똑같이 무의미한 산포가 나옵니다.

**4. 해법은 투영을 바꾸는 게 아니라 좁히는 것입니다.** 거리나 UMAP을 교체하는 대신, 관련된 1,200개로 좁히면 ① 그 안에서 전부 0인 비트가 제거되고 ② 남은 비트에 대비가 생겨 거리가 다시 퍼지고 → 진짜 군집이 나옵니다. 이것이 [부분집합 상대성](#부분집합-상대성)의 핵심이고, 아래 탐색 흐름의 `물성·모이어티 → 표적 → (좁아진 뒤) 질환` 권장 경로가 여기서 나옵니다.

- **표적**은 거의 데이터 본질입니다. "EGFR과 GPCR 사이의 거리"는 원본 토큰 공간에 존재하지 않으므로, 더 줄이려면 외부 지식(단백질 서열 유사도·공유 경로·단백질 임베딩)이 필요합니다 — 과제 계획의 **학습된 표적 예측 모델**이 바로 이 자리입니다.
- **모이어티**는 인코딩을 바꾸면(개수 기반 지문, 연속 분자 임베딩, 사전 차원축소) 전역 모양을 더 줄 수 있지만, 실사용에서 중요한 건 좁힌 뒤의 지도이고 부분집합 재적합이 그걸 이미 복구합니다.

### 확장 스냅샷 (73,864개)

약물층 12,804개는 주석이 두텁지만 화학 공간이 좁습니다. 넓히려면 "약물"이라는 기준을 버려야 하는데, **어떤 기준으로 바꿀지를 추측으로 정하면 안 된다**는 것이 측정의 결론이었습니다.

처음 세운 규칙은 "지금 약물이 치는 단백질 표적 2,898개에 100 nM 이하로 붙는 화합물"이었습니다. 수만 개를 예상했지만 **548,589개**가 나왔습니다. 사람 표적 **전체**(539,505개)보다 많습니다.

| 규칙 | 화합물 |
|---|---|
| 기존 표적에 붙는 것만 (pchembl≥7) | 548,589 |
| 사람 단백질 표적 전체 (pchembl≥7) | 539,505 |
| 구조가 있는 ChEMBL 전체 | 2,897,819 |

**표적 개수로 좁히는 것은 화합물을 좁히지 못합니다.** 측정 데이터가 소수의 인기 표적에 극단적으로 몰려 있어서, 그 표적들을 남기는 순간 화합물이 거의 다 따라옵니다. 이 2,898개가 사실상 "잘 연구된 druggable proteome" 전체입니다.

실제로 규모가 묶이는 것은 **표적당 상위 N개**입니다. 상한이 `표적 수 × N`으로 설계상 정해지고, 예산을 표적들에 고르게 써서 많이 스크리닝된 표적이 전부 가져가지 못합니다.

| 표적당 상위 | 화합물 | 약물층과 합집합 |
|---|---|---|
| 25 | 36,411 | 47,580 |
| **50** | 63,058 | **73,864** |
| 100 | 104,508 | 114,932 |

효력 기준만 올리는 방식(pchembl≥9 → 96,457개)도 규모는 맞지만 **넓어지지 않고 깊어집니다.** 1 nM에 닿는 화합물은 수십 년 최적화된 소수 표적에 몰려 있어, 이미 빽빽한 곳만 더 빽빽해집니다.

```bash
python scripts/count_expansion.py --db <chembl_37.db>    # B·C·D 규모
python scripts/count_variants.py --db <chembl_37.db>     # 실제로 묶이는 규칙 12가지
python scripts/build_snapshot_sqlite.py --db <chembl_37.db> --per-target 50 --out chembl_37_t50
```

**커버리지 — 하나는 오르고 하나는 무너집니다.**

| 도메인 | 12,804 | **73,864** |
|---|---|---|
| 물성 / 모달리티 | 100% | 100% |
| 모이어티 | 93.6% | 98.4% |
| **표적** | 46.7% | **90.8%** |
| └ mechanism (큐레이션) | 31.9% | 5.5% |
| └ activity만 (측정값) | 14.7% | 85.2% |
| **질환 (MeSH + ATC)** | 55.9% | **9.7%** |

표적 90.8%는 당연합니다 — 표적 활성을 가졌다는 이유로 뽑은 화합물이니까요. 표적 수도 4,298 → 13,060개가 됐습니다. **지금 표적 주석의 85.2%가 측정 활성에서 옵니다**: activity 층이 없었다면 이 확장은 커버리지 5.5%짜리 지도가 됐을 겁니다.

**질환은 9.7%로 무너집니다.** 적응증을 가진 화합물의 절대 개수가 6,903 → 6,905개로 **두 개 늘었습니다.** 새로 들어온 61,060개는 임상에 간 적이 없는 연구용 화합물이라 적응증 기록 자체가 없습니다. `drug_indication`의 상한이 ChEMBL 전체에서 10,073개라는 사실이 그대로 드러난 것입니다. 질환 도메인은 루트에서 90%가 미커버 띠에 놓이므로, **먼저 표적·모이어티로 좁힌 뒤 질환으로 전환하는** 흐름이 아니면 쓸모가 적습니다.

**탐색 흐름 — 첫 번째 좁히기 축이 바뀝니다.** 기획서의 걸음(전체 → 물성 1,200 → 질환 → 300 → 표적)을 두 스냅샷에서 같은 방식으로 걸어본 결과입니다. 각 단계에서 중요한 것은 군집 수가 아니라 **그 자리에 선 화합물 중 몇 개가 그 도메인의 주석을 실제로 갖고 있는지**입니다.

| 단계 | 12,804 | **73,864** |
|---|---|---|
| 루트 (물성) | 12,804 · 12군집 | 73,864 · 57군집 |
| → 물성 1,200 선택 | 1,200 · 3군집 | 1,200 · 3군집 |
| → **질환으로 전환** | 주석 **580 / 1,200 (48.3%)** · 11군집 | 주석 **91 / 1,200 (7.6%)** · 3군집 |
| → 질환에서 300 선택 | 300 · 3군집 | **91개밖에 없음** · 6군집 |
| → 표적으로 전환 | 주석 211 / 300 (70.3%) · 9군집 | 주석 66 / 91 (72.5%) · 3군집 |
| (대조) 물성 1,200 → **표적** | 주석 523 / 1,200 (43.6%) · 16군집 | 주석 **1,150 / 1,200 (95.8%)** · **29군집** |

**질환 단계가 좁히기가 아니라 절벽이 됩니다.** 1,200개 중 주석이 91개뿐이므로 다음 선택이 300개를 모을 수 없습니다 — 미커버 화합물은 적합에서 빠지고 선택 대상도 아니기 때문입니다. 반대로 **표적 단계는 43.6% / 16군집에서 95.8% / 29군집으로** 달라집니다.

즉 확장은 품질을 올리거나 내린 것이 아니라 **첫 번째 좁히기 축을 질환에서 표적으로 옮겼습니다.** 73,864개에서 권장 경로는 `물성·모이어티 → 표적 → (좁아진 뒤) 질환`이고, 질환을 먼저 보려면 약물층으로 제한해야 합니다.

> 약물층은 새 스냅샷 안에서 `max_phase >= 0.5`로 **정확히 12,804개**가 식별됩니다. 두 스냅샷을 모두 들고 다닐 필요 없이, 필터 하나로 기존 동작을 그대로 재현할 수 있습니다.

### 필터 — 좁히기의 두 번째 방법

그래서 `restrict()`를 넣었습니다. 올가미가 "지도의 이 영역"이라면 필터는 "이 조건을 가진 것만"이고, 둘 다 좁히고 재배치하므로 **같은 종류의 이동**입니다. 트리에 자기 노드로 남습니다.

| 필터 | 규칙 | 쓰는 때 |
|---|---|---|
| `drug` | `max_phase ≥ 임계값` (manifest의 `min_phase`) | 질환·ATC 주석이 필요할 때. 73,864 → 12,804 |
| `annotated` | 고른 도메인의 데이터를 가진 것만 | 미커버 띠를 걷어내고 실제 구조만 볼 때 |

임계값은 스냅샷 manifest에서 읽습니다. ChEMBL은 "철수 또는 불명"에 `-1`을 쓰는데 이 값은 어떤 실제 단계보다 작아서 단순 `>=` 비교가 **우연히** 맞습니다 — 센티넬이 바뀌면 조용히 틀리므로 결측과 함께 명시적으로 제외합니다.

**좁혀지지 않는 필터는 거부합니다.** 전부 남기면 화면에 있는 것과 똑같은 배치를 20~90초 들여 다시 계산하는 것이고, 하나도 안 남기면 배치할 것이 없습니다. 둘 다 job을 띄우기 **전에** 400으로 돌려주므로, 진행 오버레이를 보고 나서야 알게 되는 일이 없습니다.

**전환 비용은 누르기 전에 보입니다.** `GET …/nodes/{nid}/domain-coverage`가 그 노드의 화합물에 대해 도메인별 커버리지를 재서 돌려주고, 웹 UI는 그 값을 도메인 드롭다운 라벨에 직접 써넣습니다 (`질환 (disease) · 7.6%`). 15% 아래면 빨강, 40% 아래면 주황으로 경고합니다. 배치하지 않고 특성만 만들면 되므로 73,864개에서도 몇 초입니다 — **느린 것은 배치이고, 이 질문은 배치하지 않습니다.**

경고는 막지 않습니다. 7.6%짜리 질환 지도도 그 선택에 대한 정직한 그림이고, 데이터가 얇다는 사실 자체가 때로는 결과입니다.

**실제로 복구되는지 쟀습니다.** 같은 73,864개 스냅샷 안에서 두 경로를 걸었습니다.

| 경로 | 질환 주석 | 군집 |
|---|---|---|
| A. 물성 1,200 → 질환 | 91 / 1,200 (**7.6%**) | 3 |
| B. **약물층만** → 물성 1,200 → 질환 | 580 / 1,200 (**48.3%**) | 9 |

580개와 48.3%는 12,804개 스냅샷을 따로 적재해 같은 걸음을 걸었을 때와 **같은 숫자**입니다. 필터 노드의 루트 배치도 12군집 · noise 442개로 옛 스냅샷의 루트와 일치하고, 제한 후 도메인별 커버리지는 질환 55.9% · 표적 46.7% · 모이어티 93.6% — 위 [커버리지 표](#도메인별-커버리지-chembl_37-약물층-12804개)의 12,804개 열 그대로입니다.

**언제 거느냐가 무엇을 지키느냐를 정합니다.** 같은 필터를 1,200개를 고른 *뒤에* 걸면 131개가 남고 질환 커버리지는 7.6% → 69.5%가 됩니다. 비율은 B보다 높지만 화합물이 131개뿐입니다.

| 거는 시점 | 남는 화합물 | 질환 커버리지 |
|---|---|---|
| 루트에서 먼저 (B) | 1,200 | 48.3% |
| 1,200개를 고른 뒤 | 131 | 69.5% |

먼저 걸면 **개수**를 지키고, 나중에 걸면 **비율**을 지킵니다. 기획서의 걸음처럼 단계마다 일정한 규모를 유지하려면 먼저 거는 쪽입니다.

부분집합 상대성이 그대로 작동한 결과입니다. 약물층 12,804개는 73,864개 지도를 확대한 것이 아니라 **자기들끼리 다시 적합**되므로, 그 12,804개로 만든 별도 스냅샷과 같은 그림이 나올 수밖에 없습니다. 두 번째 스냅샷을 유지할 이유가 사라집니다.

**응집력 — 5.8배로 늘려도 구조는 유지됩니다.** 두 스냅샷을 `cluster_quality.py`로 같은 조건에서(상한 적용 후, 같은 시드, 귀무 포함) 다시 재고 비교했습니다.

| 도메인 | AMI 12,804 | AMI **73,864** | sil@k 12,804 | sil@k **73,864** | 군집 | noise |
|---|---|---|---|---|---|---|
| 질환 (ATC 제외) | 0.511 | **0.532** | 0.174 / 귀무 0.190 ✗ | **0.168** / 귀무 −0.011 ✓ | 44 → 47 | 6.8% → 1.8% |
| 표적 | 0.244 | 0.224 | 0.210 / 귀무 0.128 ✓ | **0.513** / 귀무 −0.030 ✓ | 58 → 812 | 6.2% → 9.2% |
| 모이어티 | 0.164 | **0.180** | 0.133 / 귀무 −0.014 ✓ | **0.103** / 귀무 −0.059 ✓ | 87 → 612 | 37.4% → 35.6% |
| 모달리티 | 0.116 | **0.120** | 0.062 / 귀무 0.073 ✗ | 0.015 / 귀무 0.047 ✗ | 43 → 197 | 4.5% → 4.4% |
| 물성 | 0.057 | **0.087** | 0.073 / 귀무 0.015 ✓ | **0.055** / 귀무 0.036 ✓ | 12 → 57 | 3.5% → 4.0% |

AMI는 네 도메인에서 오르고 표적만 0.02 내려갑니다. 그런데 **AMI는 이 확장에서 바뀐 것을 거의 보여주지 못합니다.** 실제로 달라진 쪽은 귀무와의 간격입니다. 12,804개에서는 셔플한 행렬도 쓸만한 실루엣을 냈고(질환 0.190, 표적 0.128, 모달리티 0.073) 다섯 중 셋만 귀무를 이겼습니다. 73,864개에서는 귀무가 전부 0 근처로 주저앉고 넷이 이깁니다. 표적은 0.210 → **0.513**, 귀무 대비 1.6배에서 부호가 갈릴 정도로 벌어집니다.

ATC 라벨은 두 스냅샷에서 **같은 2,543개 / 2,544개 화합물**에 붙어 있습니다. 즉 AMI·purity가 평가하는 대상은 사실상 동일한 집합이고, 확장된 지도는 그 집합을 71,000개의 낯선 화합물 사이에서 정리해야 하는 더 어려운 문제를 풀면서 네 도메인에서 더 잘 정리합니다.

> **purity는 비교에 쓰지 마세요.** 군집당 최다 라벨 비율이라 k가 커지면 자동으로 올라갑니다 (표적 48.9% → 67.5%는 군집이 58 → 812개가 된 결과입니다). k를 맞춘 `sil_at_k`와 우연을 보정한 AMI만 스냅샷 사이에서 비교할 수 있습니다.

**모달리티는 두 스냅샷 모두 기하적으로는 실패합니다** (sil@k가 귀무보다 낮음). AMI 0.12는 유지되므로 라벨과의 대응은 있지만, 26~27차원 희소 플래그로는 분리된 덩어리가 만들어지지 않습니다. 확장으로 고쳐지지 않는 문제입니다.

## 데이터 수집

```bash
.venv\Scripts\python.exe scripts\fetch_chembl.py
```

ChEMBL REST API에서 `max_phase >= 0.5` 화합물과 적응증·메커니즘·표적·단백질 계열을 받아 `data/cache/chembl_37/`에 parquet으로 저장합니다 (**약 25분**, 5GB 덤프 불필요). 릴리스 버전으로 디렉터리가 나뉘므로 특정 시점 재현이 가능합니다. 재실행은 캐시를 재사용합니다 (`--force`로 강제 갱신).

빈 디렉터리에 clone해서 실제로 재보니 **약 25분**이고, 그중 20분이 활성(activity) 층입니다 — 화합물·적응증·메커니즘은 3분이면 끝납니다. 예전에 적혀 있던 "3~6분"은 활성 층이 들어오기 전 숫자였습니다. 같은 clone이 원본과 **동일한 스냅샷**을 만듭니다 (화합물 12,804 · 적응증 44,857 · 메커니즘 5,355 · 활성 68,478 · 표적 4,298 · 단백질 계열 905, 모든 카운트 일치).

첫 `chemspace.load()`에서 RDKit 기술자·스캐폴드·모달리티·지문을 계산해 `derived/`에 캐시합니다 (12,804개 약 40초, 73,864개 약 4분, 스냅샷당 1회).

### 약물층보다 넓게 가려면 — SQLite 릴리스

REST API는 약물층까지입니다. `activity` 엔드포인트는 `__in` 배치가 20개만 넘어도 500을 돌려주고(서버 쪽 비용 제한), 무엇보다 **서로 다른 화합물이 몇 개인지 세려면 행을 전부 받아 봐야 하는데 그게 수백만 행입니다.** 규모를 정하기 전에 규모를 알 수 없습니다.

SQLite 릴리스를 한 번 받으면 같은 질문이 몇 초로 끝나고, 기준을 바꿔 볼 때마다 다시 받을 필요가 없습니다.

```bash
# 압축 5.4 GB / 해제 후 30.5 GB. 단일 연결은 300~500 KiB/s로 묶여 있으므로
# 12개 범위 요청으로 나눠 받습니다 (3.9 MiB/s, 약 25분).
scripts/parallel_fetch.sh \
  https://ftp.ebi.ac.uk/pub/databases/chembl/ChEMBLdb/latest/chembl_37_sqlite.tar.gz \
  data/chembl_dump/chembl_37_sqlite.tar.gz 12
sha256sum -c <(grep sqlite data/chembl_dump/checksums.txt)
tar -xzf data/chembl_dump/chembl_37_sqlite.tar.gz -C data/chembl_dump
```

`parallel_fetch.sh`는 조각마다 따로 이어받고, **조립 전에 조각 길이를 검사합니다.** 이 검사가 실제로 깨진 파일을 잡았습니다 — 연결이 끊겼을 때 `curl --retry`가 같은 구간을 처음부터 다시 받아 덧붙여서 조각 하나가 919 MB(정상 480 MB)가 됐습니다. 그래서 재시도는 curl이 아니라 바깥 루프가 하고, 매 회차가 디스크에 실제로 있는 바이트 수에서 오프셋을 다시 계산합니다.

`scripts/build_snapshot_sqlite.py`가 여기서 **REST 경로와 똑같은 6개 테이블·똑같은 컬럼 이름**으로 스냅샷을 만듭니다 (73,864개 기준 38초). 다운스트림(`Dataset.load`, 도메인, 캐시)은 전혀 바뀌지 않습니다. 릴리스마다 컬럼이 바뀌는 일이 있어 **시작 전에 스키마를 검사하고**, 어긋나면 null 컬럼을 조용히 쓰는 대신 테이블·컬럼 이름을 대고 멈춥니다.

## 사용

```python
import chemspace

ds = chemspace.load()
print(ds.coverage())

s = chemspace.ExplorationSession(ds)
s.root("physchem")                        # n1: 전체를 물성으로 배치
s.select("n1", clusters=[3, 4])           # n2: 영역 선택 (물성 유지)
s.switch_domain("n2", "disease")          # n3: 같은 화합물, 질환으로 재배치
s.select("n3", clusters=[0])              # n4
s.switch_domain("n4", "target")           # n5

s.restrict("n1", "drug")                  # 약물층(임상 단계)만 — 73,864 → 12,804
s.restrict("n3", "annotated")             # 그 도메인의 데이터를 가진 것만
s.domain_coverage("n2")                   # 전환 전에 각 도메인이 몇 개를 덮는지

print(s.breadcrumb("n5"))
print(s.tree())

s.describe("n4")       # 이 선택은 무엇인가 — 다섯 도메인 동시 요약 + 도메인별 커버리지
s.cluster_table("n5")  # 군집별 프로파일 (현재 도메인 + 물성 + 모달리티)
s.history()            # 단계 기록
s.frame("n5")          # 좌표·군집이 붙은 화합물 테이블
s.save("data/sessions/run1")
```

`describe()`는 영역을 선택한 직후 가장 자주 하게 되는 질문에 답합니다. 물성 지도에서 고른 영역도 결국 어떤 치료영역·표적 계열·스캐폴드의 혼합이고, 각 도메인의 커버리지를 함께 보여주므로 근거가 얇은 요약을 사실로 읽는 일을 막습니다.

### 사용자 — 공유 서버에 올리기 전에

혼자 쓰는 노트북에서는 필요 없던 것이고, **공유 호스트에서는 둘이 필요합니다.** 하나는 모르는 사람을 막는 일이고, 다른 하나가 더 급했습니다.

```javascript
post(`/api/sessions/${sessionId}/save`, { name: "web" })   // 고치기 전
```

모든 브라우저가 같은 이름을 보냈습니다. **두 번째로 저장하는 사람이 첫 번째 사람의 탐색 트리를 지웠습니다** — 같은 경로에, 경고 없이. 저장 경로를 사용자에서 끌어내는 것이 이 문제의 해법이고, 그건 사내망에서도 인터넷에서와 똑같이 필요합니다. "방화벽 안이니까 생략"으로 시작하면 **"사용자라는 개념이 없다"가 저장 로직·세션 조회·UI에 그대로 굳어서**, 나중에 열 때 그걸 다 걷어내야 합니다. 나중이 비싼 건 네트워크가 아니라 이쪽입니다.

| | 하는 일 |
|---|---|
| `scripts/manage_users.py` | `add` · `passwd` · `list` · `remove`. 비밀번호는 `getpass`로 받아 화면·명령행·셸 기록 어디에도 안 남습니다 |
| `data/users.json` | scrypt 해시 (n=2¹⁴, r=8 — 시도당 약 0.14초). 평문은 저장되지 않습니다 |
| `data/cookie_secret` | 쿠키 서명 키. 첫 실행 때 생성되고, **지우면 전원 로그아웃**입니다 |

설계에서 신경 쓴 것들입니다.

- **등록된 사용자가 없으면 서버가 뜨지 않습니다.** 누군가 계정을 만들 때까지 열린 채로 돌아가는 상태가 곧 서버에 올라가 그대로 남는 상태입니다
- **차단은 미들웨어 한 곳의 allow-list**입니다. 엔드포인트마다 데코레이터를 다는 방식은 **나중에 라우트를 추가하면서 잊는 순간** 뚫립니다. 여기서는 새 라우트가 기본적으로 닫혀 있고, 여는 쪽이 의식적인 작업입니다. 테스트가 15개 엔드포인트 전부 401인지 확인합니다
- **세션에 주인이 있습니다.** 전에는 12자리 세션 id를 아는 사람이면 누구나 남의 트리를 읽을 수 있었습니다. 지금은 조회마다 주인을 확인하고, 남의 것은 403이 아니라 **404**입니다 — 존재한다고 알려주면 id를 떠볼 수 있습니다
- **쿠키는 `name|만료`에 대한 HMAC**입니다. 만료가 서명 안에 들어 있어서 뒤로 늘려 붙일 수 없고, `HttpOnly`라 페이지 스크립트가 읽지 못하며, `SameSite=Lax`라 다른 사이트가 타고 들어오지 못합니다
- **이름에 점이 없습니다.** 예전 저장 이름 규칙 `^[A-Za-z0-9._-]{1,64}$`은 `..`를 통과시켰고, 이름이 곧 디렉터리 이름이라 저장 경로가 밖으로 나갈 수 있었습니다. 문법에서 점을 빼 막고, 경로를 만들 때 포함 관계도 다시 확인합니다
- **실패 메시지는 하나**입니다. "그런 사용자 없음"과 "비밀번호 틀림"을 구분하면 로그인 폼이 계정 조회 수단이 됩니다. 없는 사용자도 scrypt를 한 번 돌려 **응답 시간까지 같게** 만듭니다

> **`--secure-cookie`는 TLS를 앞에 세운 뒤에 켜세요.** `Secure` 쿠키는 평문 HTTP로는 아예 전송되지 않아서, 사내 `http://` 호스트에서 켜면 로그인이 조용히 전부 실패합니다. 그래서 기본값이 꺼짐입니다.

### 서버에 올리기 — 사내망

실제로 올려서 돌리고 있는 구성입니다 (Rocky Linux 9.8, 64코어, **sudo 없는 계정**).

```bash
git clone https://github.com/baaaam771/Chemical_Space.git ~/chemspace
cd ~/chemspace && uv sync --python 3.12 --all-extras && uv pip install -e .

# 스냅샷은 다시 만들지 말고 복사하세요 — 24 MB입니다
scp -r <작업PC>:…/data/cache/chembl_37_t50  data/cache/
scp -r <작업PC>:…/data/cache/placements     data/cache/

.venv/bin/python scripts/manage_users.py add <이름> --generate

systemctl --user daemon-reload

.venv/bin/python scripts/warm_cache.py    # 도메인 5개 루트 미리 계산
```

**sudo가 필요 없습니다.** `/etc/systemd/system`에 넣으려면 root가 필요하지만 `systemctl --user`는 아니고, `loginctl enable-linger`는 본인 계정에 대해 스스로 걸 수 있습니다. 그러면 ssh를 끊어도, 재부팅해도 서비스가 돌아옵니다.

**스냅샷을 서버에서 다시 만들지 마세요.** 30 GB SQLite 릴리스를 다시 받고 빌드할 이유가 없습니다 — parquet 스냅샷 24 MB와 배치 캐시 720 KB를 복사하면 끝이고, **캐시를 같이 보내면 첫 접속자도 기다리지 않습니다.** 실제로 사내망 너머 브라우저에서 첫 지도까지 **1초**였습니다 (캐시 없이는 88초).

막힌 자리 둘을 적어둡니다.

- **`218/CAPABILITIES`로 서비스가 안 떴습니다.** `PrivateDevices`·`ProtectSystem`·`ProtectHome`을 넣었는데, 사용자 유닛에는 그 권한이 없습니다. 이 수준에서는 의미도 거의 없습니다 — 어차피 같은 계정으로 도니까요. 진짜 격리는 전용 계정 + 시스템 유닛이고 그건 root가 필요합니다. 지금은 `NoNewPrivileges`만 겁니다
- **`journalctl --user -u chemspace`에 아무것도 없습니다.** 이 호스트에 사용자 저널이 영구 설정돼 있지 않습니다. 로그가 사라지는 서비스는 디버깅할 수 없으니 `data/chemspace.log`로 직접 씁니다 (로테이션은 직접 하세요)

> **이 호스트는 방화벽이 꺼져 있습니다** (`firewall-cmd --state` → not running). `--host 0.0.0.0`은 알려준 사람뿐 아니라 **이 머신까지 경로가 닿는 전부**에게 열린다는 뜻입니다. 그게 아니라면 `127.0.0.1`로 두고 ssh 터널을 쓰세요.

|---|---|
| 상태 | `systemctl --user status chemspace` |
| 로그 | `tail -f ~/chemspace/data/chemspace.log` |
| 재시작 | `systemctl --user restart chemspace` |
| 중지 | `systemctl --user stop chemspace` |

### 선택 방법 세 가지를 섞을 수 있습니다

| 조작 | 결과 |
|---|---|
| 드래그 (올가미/박스) | 영역 안의 화합물로 선택을 **교체** |
| **shift + 클릭** | 화합물 하나를 선택에 **더하거나 뺌** |
| **shift + 드래그** | 두 번째 영역을 **덧붙임** |
| `선택 해제` 버튼 / 빈 곳 클릭 | 선택을 비움 |

섞어 쓸 수 있는 이유는 선택이 **점 인덱스 집합** 하나로만 표현되고, 엔진의 `select(point_indices=...)`가 그 집합이 어떤 조작에서 나왔는지 묻지 않기 때문입니다. 다만 드래그에 개별 조정이 섞이면 올가미 궤적은 더 이상 그 선택을 설명하지 않으므로, 탐색 경로에 `polygon_partial: true`가 함께 기록됩니다 — 저장한 세션을 나중에 다각형만 보고 복원하려다 조용히 다른 화합물 집합을 얻는 일을 막기 위해서입니다.

개별 조정이 들어간 순간 plotly가 그린 선택 영역 외곽선은 사라집니다. plotly는 그 도형으로부터 선택을 계속 다시 계산하기 때문에, 외곽선을 남겨 두면 shift+클릭으로 추가한 점이 선택에는 들어 있는데 화면에는 강조되지 않습니다. 실제 선택과 어긋난 외곽선보다 외곽선이 없는 편이 낫습니다. 아래 탭에 `이 선택은 무엇인가`(다섯 도메인 동시 요약) · `군집 프로파일` · `탐색 경로` · `화합물` 표가 붙습니다.

### 설계 결정 세 가지

**1. 배치는 요청 안에서 끝낼 수 없습니다.** 전체 배치는 도메인에 따라 12,804개에서 6~32초, 73,864개에서 20~223초입니다. 브라우저와 프록시가 먼저 끊고, 사용자는 빈 화면만 봅니다. 그래서 `root`·`select`·`switch`는 **작업 ID를 즉시 반환**하고 브라우저가 폴링합니다. 진행 오버레이가 무엇을 하는 중인지와 경과 시간을 보여줍니다.

```
POST /api/sessions/{sid}/select  →  {"job_id": "...", "state": "pending"}
GET  /api/jobs/{job_id}          →  {"state": "running", "elapsed": 12.4}
                                 →  {"state": "done", "result": "n4"}
```

작업은 스레드 풀(기본 2개)에서 돕니다. UMAP·HDBSCAN은 NumPy/numba 안에서 GIL을 놓으므로 스레드로 충분하고, 프로세스로 띄우면 데이터셋을 통째로 보내야 합니다. 이 작업들은 CPU 바운드라 워커를 늘려도 빨라지지 않고 서로 느려지기만 해서 의도적으로 좁게 뒀습니다.

**2. 배치 결과를 디스크에 캐시합니다** (`data/cache/placements/`). 배치는 (도메인, 화합물 집합, 설정)의 순수 함수라서 캐시 적중은 재계산과 같은 값을 돌려줍니다. 덕분에 두 번째 방문부터 첫 지도가 즉시 뜹니다. jaccard 도메인이 프로세스 간 비트 재현이 안 되는 점을 생각하면, 캐시는 오히려 **두 실행이 같은 좌표를 갖게 해 주는 유일한 수단**입니다. `--no-cache`로 끌 수 있습니다.

배포 후나 ChEMBL 갱신 후에 한 번 돌려 두면 첫 방문자도 기다리지 않습니다.

```bash
.venv\Scripts\python.exe scripts\warm_cache.py
```

**3. 데이터셋은 한 번만 적재해 공유합니다.** 생성 후 읽기 전용이고 수백 MB라 브라우저 세션마다 복사할 이유가 없습니다. 탐색 트리만 세션별로 갖습니다. 세션은 메모리에 있고 재시작하면 사라지지만, 비싼 부분(배치)은 디스크 캐시에 있으므로 다시 만들어도 즉시 복원됩니다. 보존할 것은 `세션 저장` 버튼으로 `data/sessions/`에 남깁니다.

### 왜 plotly.js인가

12,804점은 `scattergl`로 충분하고 올가미 선택이 내장이라 빌드 단계가 필요 없습니다. **10만 점을 넘기면 deck.gl로 교체해야 하고, 그때도 백엔드는 그대로입니다** — 프런트엔드가 보관하는 상태는 세션 ID, 노드 ID, 선택한 점 인덱스 집합뿐입니다.

산점도를 **트레이스 하나**로 유지하는 것도 의도적입니다. 군집마다 트레이스를 나누면 범례를 공짜로 얻지만, 클릭 이벤트의 `pointIndex`가 노드 인덱스와 더 이상 일치하지 않아 shift+클릭마다 인덱스 재매핑이 필요해집니다.

> UI 자산(`app.js`, `style.css`)은 `Cache-Control: no-store`로 보내고 URL에 파일 mtime을 붙입니다. 고정된 이름으로 서빙하면 브라우저가 수정된 파일을 받지 않고 예전 코드를 계속 실행하는데, 페이지는 멀쩡히 뜨기 때문에 이 실패는 조용히 지나갑니다.

> plotly.js는 CDN에서 가져옵니다. 내부망·폐쇄망 배포에서는 `static/`에 파일을 넣고 `index.html`의 `src`만 바꾸면 됩니다. 다른 CDN 의존성은 없습니다.

### 재현성 — 측정한 사실

임베딩 `random_state`는 기본 고정입니다. 다만 **그것만으로 완전한 재현이 보장되지는 않습니다.** 동일한 코드로 같은 체인을 서로 다른 프로세스에서 두 번 실행해 좌표 해시를 비교했습니다.

| 노드 | 도메인 / 거리 | 좌표 | 군집 라벨 |
|---|---|---|---|
| n1 (12,804개) | 물성 / euclidean | **동일** | 동일 |
| n2 (1,200개) | 물성 / euclidean | **동일** | 동일 |
| n3 (1,200개) | 질환 / **jaccard** | **다름** | **동일** |

euclidean 도메인(물성·모달리티)은 비트 단위로 재현됩니다. **jaccard 도메인(질환·표적·모이어티)은 좌표가 실행마다 미세하게 달라집니다** — pynndescent의 근사 최근접이웃 탐색 때문이며 `random_state`로 완전히 묶이지 않습니다. 위 측정에서 군집 라벨은 동일했지만, 그것이 보장되지는 않습니다. 실제로 스모크 테스트를 반복하면 하위 노드의 군집 개수가 달라지는 것이 관찰됩니다(ARI 결론은 유지).

**기록의 재현성은 다른 경로로 보장됩니다.** `session.save()`가 좌표와 군집 라벨을 그대로 저장하므로, 저장된 탐색 경로는 언제 다시 열어도 같은 지도를 보여줍니다. 재계산이 아니라 보존으로 해결합니다.

### 속도

`random_state`를 설정하면 UMAP은 단일 스레드로 동작합니다. 전체 배치 시간의 대부분이 이 때문입니다 — 12,804개에서 6~32초, 73,864개에서 20~223초(도메인별, numba 캐시가 더워진 뒤). 1,200개 이하로 좁힌 뒤의 단계는 수 초면 끝납니다.

전체 집합을 여러 도메인으로 바꿔 보는 탐색이 많다면 멀티코어로 전환하세요 (약 4배 빠름, 대신 좌표 재현성을 완전히 포기).

```python
s = chemspace.ExplorationSession(ds, embed=chemspace.EmbedConfig(random_state=None))
```

저장된 세션은 좌표를 보존하므로, 이 설정은 새로 만드는 노드에만 영향을 줍니다.

특성 계산 자체는 모든 구간에서 저렴합니다 (측정값, ChEMBL_37):

| 도메인 | 12,804개 | 1,200개 | 300개 |
|---|---|---|---|
| 물성 | 13열 / 0.02초 | 13열 | 13열 |
| 질환 | 374열 / 18MB | **995열** | 932열 |
| 표적 | 81열 | 145열 | 126열 |
| 모이어티 | 2,048열 / 100MB / 0.37초 | 1,601열 | 811열 |
| 모달리티 | 26열 | 21열 | 18열 |

질환 도메인이 12,804개에서 374열인데 1,200개 부분집합에서 995열로 **늘어나는** 것이 부분집합 상대성입니다. 전체에서는 지지도 임계가 25라 희귀 적응증이 잘려 나가지만, 1,200개로 좁히면 임계가 2로 내려가 그 집합 안에서 의미를 갖는 세밀한 적응증이 살아납니다. 느린 쪽은 특성 계산이 아니라 UMAP입니다.

### 더 큰 규모로 갈 때 — 직접 재 보세요

`scripts/bench_placement.py`가 배치 비용이 화합물 수에 따라 어떻게 늘어나는지 재고,
측정값에 `seconds ~ n^k`를 적합해 50만 개와 ChEMBL 전체(290만)로 투영합니다.

```bash
python scripts/bench_placement.py                   # CPU (현재 경로)
python scripts/bench_placement.py --gpu             # RAPIDS cuML 경로까지
```

측정값 — **GPU** (RTX PRO 5000 Blackwell 48GB, cuML 26.10, 합성 행렬):

| n | 물성 (euclidean/13) | VRAM | 질환 (jaccard/400) | VRAM |
|---|---|---|---|---|
| 25,000 | 0.2초 | — | 0.8초 | — |
| 50,000 | 0.3초 | — | 1.7초 | — |
| 100,000 | 0.8초 | 2.2 GB | 4.1초 | 34.4 GB |
| 200,000 | 2.7초 | 6.3 GB | 16.4초 | 34.5 GB |
| 500,000 | 34.9초 | 24.9 GB | 72.9초 | 34.6 GB |

CPU 대비 20~110배입니다. 세 가지가 눈에 띕니다.

**`random_state=0`을 포기할 이유가 없습니다.** cuML 문서는 `random_state`가 느리다고 하지만, 이 워크로드에서는 `build_algo="nn_descent"`와 같거나 오히려 빠릅니다. 좌표 재현성이 공짜입니다. (그리고 nn_descent는 희소 jaccard를 아예 지원하지 않습니다 — `NotImplementedError`.)

**Jaccard의 VRAM은 n과 무관하게 34.5 GB로 평평합니다.** 고정 크기 작업 버퍼를 잡기 때문이고, 쪼갤 수 없습니다 — `brute_force_knn`의 배치 분할(`knn_n_clusters > 1`)이 허용하는 거리 목록에 jaccard가 없습니다. 쓸 수 있는 메모리가 그보다 적으면 그냥 실패합니다 (여유 10.5 GB에서는 50,000개에서 OOM).

**반대로 euclidean의 VRAM은 n^1.45로 늘어납니다.** 13열짜리 조밀 행렬인데도 500,000개에서 24.9 GB를 씁니다. 48 GB 카드는 **약 79만 개에서 한계**이고, 290만 개는 316 GB가 필요해 들어가지 않습니다. 거기까지 가야 한다면 euclidean은 `knn_n_clusters > 1`로 kNN을 배치 분할할 수 있습니다 (이 옵션은 l2/euclidean에서만 허용됩니다).

측정값 — **CPU** (20코어 Windows 기계, `random_state=0`이라 **단일 스레드**, 합성 행렬):

| n | 물성 (euclidean/13) | 질환 (jaccard/400) |
|---|---|---|
| 25,000 | 11.9초 | 48.1초 |
| 50,000 | 31.6초 | 112.2초 |
| 100,000 | 87.1초 | 285.2초 |
| 200,000 | 306.9초 | 440.0초 |
| **500,000 (투영)** | **15~20분** | **23~37분** |
| **2,897,819 (투영)** | **3.0~5.0시간** | **2.6~5.9시간** |

투영에 폭이 있는 것은 jaccard의 200,000 지점이 추세에서 벗어나기 때문입니다 (100k→200k가 2배 데이터에 1.54배 시간). 이 점을 넣으면 지수가 n^1.09, 빼면 n^1.28이 됩니다. 합성 행렬은 밀도가 고정이라 n이 커질수록 Jaccard 거리가 한 점으로 몰리는데, 실제 데이터에는 없는 성질입니다 — **보수적인 쪽(n^1.28)을 기준으로 보는 편이 안전합니다.** 이 표의 한계이기도 합니다: 모양은 실제 도메인과 같지만 군집 구조가 없는 난수 행렬입니다.

GPU 경로는 두 가지 모드를 따로 잽니다. `fast`(`build_algo="nn_descent"`)는 가장 빠르지만
재현성을 깨고, `repro`(`random_state=0`)는 재현 가능하지만 문서상 더 느리고 메모리를 더 씁니다
— CPU에서와 같은 선택입니다.

**cuML로 옮길 때 걸릴 법한 두 지점은 우리에게는 문제가 되지 않습니다.**
cuML UMAP의 `jaccard`는 희소 입력에서만 지원되는데 질환·표적·모이어티 행렬은 원래 희소
이진이고, cuML HDBSCAN은 euclidean 전용인데 우리는 특성 공간이 아니라 **2-D 좌표 위에서**
군집화하므로 정의상 euclidean입니다. 특성 공간에서 군집화하는 설계였다면 5개 도메인 중 3개가
GPU 경로에서 막혔을 겁니다.

VRAM은 제약이 아닙니다. 290만 개 전체라도 물성 행렬 151MB, 질환 희소 행렬 약 100MB,
kNN 그래프 약 350MB로 한 장에 들어갑니다. 또 cuML UMAP/HDBSCAN은 단일 GPU이므로
카드 두 장이 한 배치를 두 배 빠르게 하지는 않습니다 — **배치 두 개를 동시에** 돌립니다
(작업 큐가 이미 워커 2개라 그대로 맞습니다).

이 스크립트는 `--skip-cpu`를 주면 chemspace를 전혀 import하지 않으므로, **파일 하나만
GPU 서버에 복사해** numpy·scipy·cuml만으로 돌릴 수 있습니다.

> RAPIDS는 Linux(또는 WSL2)에서 동작하고 compute capability 7.0 이상을 요구합니다.
> Blackwell(RTX PRO 5000 등, cc 12.0 / sm_120)은 CUDA 12.8 이상과 RAPIDS 25.02 이상이
> 필요합니다. 설치 명령은 [RAPIDS 설치 선택기](https://docs.rapids.ai/install/)를 쓰세요.

### 군집 세분도

`min_cluster_size`는 부분집합 크기의 제곱근에 비례해 자동 조정되되 **40에서 멈춥니다** (300 → 9, 1,200 → 17, 6,400 이상 → 40). 선형 비례(`n/50`)로 두면 12,804개에서 군집이 6개만 나와 "영역 선택"을 해도 대부분이 남습니다. 직접 지정하려면 `ClusterConfig(min_cluster_size=...)`를 넘기세요.

**상한은 측정해서 붙였습니다.** 제곱근 규칙은 12,804개에서 맞춰 둔 것(57)이라 지도가 커질수록 더 큰 군집을 요구합니다. 73,864개에서는 136을 요구했고 그 결과가 이렇습니다.

| 도메인 | min_size | 군집 | noise | AMI |
|---|---|---|---|---|
| 모이어티 | **136** | 7 | 17.6% | **0.033** |
| 모이어티 | 60 | 265 | 52.6% | **0.181** |
| 모이어티 | 40 | 601 | 37.5% | 0.168 |
| 표적 | **136** | 128 | **51.1%** | 0.242 |
| 표적 | 40 | 810 | **8.9%** | 0.236 |
| 표적 | 20 | 1,284 | 3.8% | 0.226 |

모이어티는 확장 전 12,804개에서 0.130이었으므로, **136에서의 0.033은 데이터가 흐려진 게 아니라 규칙이 지도를 뭉갠 결과**입니다. 표적은 AMI가 0.226~0.251로 거의 평평한데 noise만 3.8%에서 51.1%로 벌어집니다 — **AMI는 "군집에 들지 못한 화합물"을 보지 않으므로, 이 도메인에서는 AMI로 파라미터를 고를 수 없습니다.**

지수를 바꾸는 대신 상한을 둔 이유는 이 파라미터의 뜻이 "군집이라 부를 만한 최소 묶음"이고 그건 **화학에 대한 판단**이기 때문입니다. 유사체 40개짜리 계열은 지도에 1만 개가 있든 100만 개가 있든 계열입니다. 제곱근은 작은 부분집합에서 여전히 필요합니다(고정값이면 300개짜리가 전부 noise가 됩니다). 상한은 n = 6,400 위에서만 걸립니다.

**12,804개에서도 40이 57보다 낫습니다** (모이어티 AMI 0.179 대 0.148, 표적 noise 13.4% 대 22.1%, 나빠지는 도메인 없음). 큰 쪽을 위해 작은 쪽을 희생한 선택이 아닙니다.

```bash
python scripts/tune_min_cluster.py                               # 현재 스냅샷
python scripts/tune_min_cluster.py --snapshot data/cache/chembl_37
```
